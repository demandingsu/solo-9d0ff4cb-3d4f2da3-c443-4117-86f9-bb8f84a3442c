# 压力机振动录波演示

诊断员听到压力机异响后，需要把异常前后的原始振动波形交给故障分析人员。本项目用
FastAPI 实现一个录波网页，并附带本地仪器模拟器，可在浏览器里完整演示：

- 服务端通过**一条 TCP 连接**接收仪器逐行发送的 CSV（`序号,采样时间,加速度`）；
- 页面实时显示采集状态（连接、连续采样数、累计接收、断点、最新采样、波形预览）；
- 点击「发起录波」时，以**服务端此刻最后收到的采样**为界，保留含该条在内的
  **前 100 条 + 后 200 条**，共 300 条；
- 前段连续采样不足 100 条时拒绝录波（HTTP 409）；
- 多个页面同时触发的录波各自独立、互不影响，重叠录波均能完整完成；
- 关闭浏览器页面不影响服务端采集与录波，已完成文件仍可下载；
- TCP 断线、无法解析的行、序号不连续都会判定为断点：**跨越断点的录波失败且不提供
  下载**，历史缓存清空，重新积累连续 100 条后才能再次录波；已完成的录波文件不受
  影响，始终可以下载。

## 目录结构

```
app/                 录波服务（FastAPI + 单条 TCP 采集连接）
  app.py             HTTP 路由与页面
  capture.py         采样缓存、录波窗口、断点判定（核心逻辑）
  instrument.py      单连接 TCP 客户端，断线自动退避重连
  static/            录波网页（原生 HTML/CSS/JS，无构建步骤）
  Dockerfile
simulator/           仪器模拟器（TCP 发样 + HTTP 控制面板）
  simulator.py
  static/            模拟器控制网页
  Dockerfile
tests/               pytest 单元/接口测试与端到端冒烟脚本
docker-compose.yml
```

## 快速开始

```bash
docker compose up --build
```

启动后打开：

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 录波页面 | http://localhost:8000 | 看采集/录波状态、发起录波、下载 CSV |
| 仪器模拟器 | http://localhost:8001 | 逐批发样、跳号、断线、连续自动发样 |

录波服务会自动连接模拟器的 TCP 5000 端口（容器网络内）。模拟器的 5000 端口也映射
到宿主机，可用 `nc localhost 5000` 直接观察协议。

### 演示脚本

1. 打开录波页面和模拟器页面，确认状态变为「仪器已连接 / 可录波」。
2. 在模拟器点两次「发送 50 条」（或直接「+100 条」）。录波页面连续采样达到 100，
   「发起录波」按钮变为可用。
3. 点「发起录波」，再发 4 批 × 50 条。进度走完 300 条后浏览器自动下载
   `waveform_R0001_anchor_<序号>.csv`。
4. **重叠录波**：再积累 100 条以上，开两个录波标签页，各点一次「发起录波」，
   两个录波独立完成并各自下载。期间可以关闭其中一个页面，另一个照常完成。
5. **跳号失败**：发起一次录波后，在模拟器点「发送一条跳号采样」。进行中的录波
   立即变为「失败」，下载返回 409；页面提示需重新积累连续 100 条。
6. **断线恢复**：录波进行中点「断开 TCP 连接」。录波失败，录波服务自动重连
   （0.5～5 秒退避），重新发送 100 条后恢复可录波。此前已完成的文件仍可下载。
7. 「开始连续发送」可按固定速率自动发样，方便长时间观察与重叠录波演示。

## HTTP 接口（录波服务 :8000）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/status` | 连接、流统计、全部录波状态 |
| GET | `/api/preview?count=240` | 最近连续采样（波形预览） |
| POST | `/api/recordings` | 发起录波；不足 100 条时返回 409 |
| GET | `/api/recordings` | 录波列表 |
| GET | `/api/recordings/{id}` | 单个录波状态 |
| GET | `/api/recordings/{id}/download` | 完成后下载 CSV；未完成/失败返回 409 |

模拟器（:8001）提供 `POST /api/send`、`POST /api/skip`、`POST /api/disconnect`、
`POST /api/auto` 和 `GET /api/state`。

## 录波与断点语义

- 录波在服务端创建，页面只负责轮询展示；页面关闭后录波继续。
- 录波窗口固定为 300 条：基准采样（点击时最后一条）及其之前 99 条，再加上其后
  200 条。
- 断点来源：TCP 连接断开、收到无法解析的行、序号不等于上一条 +1。
- 断点发生时：所有进行中的录波标记失败并清空数据；历史缓存清空；已完成录波保留。
- 新连接收到的第一批连续采样重新计数，连续满 100 条后 `can_record` 恢复为真。
